# Thanksgiving Photo Hunt

Phone website for a neighborhood photo scavenger hunt. Players find the spot in each photo and send a picture from there. The server quietly marks each one right or wrong by GPS, and nobody sees the results until the organizer reveals them at the end.

- Player: https://photo-hunt.twmdemuth.workers.dev
- Admin: https://photo-hunt.twmdemuth.workers.dev/admin (main password in `admin-password.txt`, not committed). Setup → Admins → "Create invite link" lets someone set their own admin password (one-time link, 7 days).
- Map for players: https://photo-hunt.twmdemuth.workers.dev/area shows the play area and home base (no photo spots), with a QR code and a notes box. "Download picture" makes a PNG to text the family; "Print or PDF" prints it. Linked from the admin Map tab ("🖨 Map for players").
- TV at home base: https://photo-hunt.twmdemuth.workers.dev/tv (no password, no buttons). It only gets what the room may see: by default no locations at all (no player dots, trails or photo spots) and no points or right/wrong until the reveal. Click the screen once for sound and full screen. Everything else is controlled from the admin Live tab → "📺 TV" card (on Dad's phone): No spoilers, players on the map, names, trails, photo spots, new-photo pop-ups, join code in the corner, sound, results show speed, and buttons to show the results again, skip to the winner, or go back to the map. Before the start it shows the QR code and each team's name with everyone who has joined. Admin Live tab → "📺 Play How to play on the TV" runs a two-minute animated demo of how to play.

## How a game runs
1. Players scan the QR code and wait in the lobby (their team's color), where a short "How to play" card guide opens by itself the first time (two parts, swipe or Next / Back: how the game works, then how to use the app; "Show me how to play" in the lobby and the ? button in the game open it again), see everyone, and switch teams. The lobby shows whether their location is on; if it's blocked, a "Fix it" button gives step-by-step help for their phone (iPhone Safari or another browser, Android Chrome or Samsung Internet, Screen Time limits on kids' phones, or when opened inside another app). "Try again" reloads the page, because Safari keeps saying no until the page is opened fresh, even after Settings are fixed. If a phone only shares a rough location (Precise Location off), it says how to turn it on. The admin's player list shows each phone's location status (📍 ok / no location yet / location off). Admin Map tab → "🏠 Set home base" puts a pin on every player's map and the TV (drag to move); at the end, phones say "Head back to …" with walking directions. Admin presses Start: a 10-second countdown on every phone and the TV, then the hunt opens and teams are locked.
   - Random teams (Live tab → 🎲 Random teams, before the start): players join without picking a team and can't switch; the lobby and TV just list who's here. Tick "Adult" next to the grown-ups, pick the number of teams (2–8), and press Shuffle: adults are spread first so every team gets at least one (if there are enough), then everyone else evens out the sizes. Only the admin sees the shuffle until "Reveal the teams": then each phone shows "You're on the Red team!" with their teammates, and the TV fills in the team columns with a fanfare. Shuffle again hides them until the next reveal; people joining after the shuffle go to the smallest team. The game can't start until the teams are revealed.
2. Players send a picture + location for each spot. If a phone goes past the orange line, it buzzes and shows "You're outside the game area"; the admin's player list and map flag them too. Admin Live tab → "📣 Message everyone" pops a message up on every phone (with a buzz) and big on the TV. They see only "Sent", how many photos each team and person has sent, teammates on the map, and "Red team found something!" pop-ups.
3. Server marks each answer: within the photo's radius = yes; close call = judge queue; far = no (the judge can still approve it). "Send it again" replaces a team's answer; only the newest counts.
4. When the game ends, phones lock to "Game over! See the results on the main screen." Admin clears the judge queue, then presses Reveal results for the TV.
5. The admin can change any call at any time (Yes / No / Reset to what GPS said). The admin can remove a player (their phone goes back to the join screen; photos they sent stay with the team). After the game, "Reset and play again" clears every photo sent and all trails and removes every player (everyone joins again); teams and photos stay.
6. Photo sets (Setup tab → Photo sets) keep several sets of hunt photos, each with its play area and home base, so each round can use different spots without re-uploading. The game remembers which set it's using ("in use"). "🆕 Start a new set…" asks for the new set's name, saves the photos here into the set in use (or asks a name for them if they aren't in a set yet), then clears the game so you can add the new set's photos; the play area and home base stay. "Load" switches to another set and saves the one in use first, so nothing is lost. "💾 Save to …" saves the set in use right away. Switching only works before the game starts (after a game, reset it on the Live tab first), and it clears any photos already sent. Sets share pictures with games, so deleting a set never deletes a picture. Test locally: `node scripts/test-sets.mjs http://localhost:8787 <pw>` and `node scripts/test-set-switch.mjs http://localhost:8787 <pw>`.

## Stack
Cloudflare Worker (`src/worker.js`) serving static files from `public/` plus a JSON API. Photo uploads accept JPEG, PNG and iPhone HEIC; HEIC is decoded in the browser with `public/vendor/heic-to.js` (libheif, LGPL, loaded only when needed) and the location is read from the photo with exifr. D1 for data (`schema.sql`), Workers KV for photos (swap to R2 later: change `putImage`/`serveImage` and the binding).

## Commands
```
npm run dev        # local server on :8787 (password in .dev.vars)
npm run deploy     # deploy to workers.dev
npm run db:remote  # apply schema.sql to a new database
```
Updates: every write bumps `games.version`; phones poll every 4 s and the TV every 3 s with the last version they saw, and get a tiny "nothing new" reply until it changes. Locations are saved every 12 s.

Existing databases: apply each file in `migrations/` once, e.g.
`npx wrangler d1 execute photo-hunt-db --remote --file=migrations/001-hidden-results.sql`

Tests (local only, they wipe the current game): `node scripts/seed.mjs http://localhost:8787 <pw> && node scripts/test-rules.mjs http://localhost:8787 <pw>`
